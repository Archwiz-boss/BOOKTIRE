# CPAMI 二維書表資料編輯器

這是不依賴雲端服務的前端。13 表、596 欄及欄位順序由不含案件內容的 `schema/data_txt_schema.json` 定義；B／C／D 系列的道路、勘驗、逐月材料、附件、變更使用檢討與昇降設備由 `schema/case_extension_schema.json` 定義。瀏覽器負責編輯與來源資料對接，Python 服務負責嚴格解析並輸出 CP950／Big5。

## 啟動

有兩個彼此獨立的啟動方式：

- `Start_CPAMI_Editor.bat`：原本的無資料庫模式，使用 `0.0.0.0:8765`。
- `Start_CPAMI_Editor_SQLite.bat`：共用範本模式，使用 `0.0.0.0:8766`；只把範本存到 `runtime/sqlite/cpami_templates.db`，不保存完整案件。

兩個 BAT 都會自動開啟本機網址。服務運行期間終端視窗會保持開啟；關閉視窗或按 `Ctrl+C` 就會停止服務。SQLite 模式第一次啟動會自動建立資料庫與資料夾，不需要 Docker、MySQL 或額外 Python 套件。

也可以在 PowerShell 手動執行：

```powershell
cd C:\Users\chuck\Desktop\CLAUDE\BOOKTIRE\cpami-form-editor
python -X utf8 .\server.py
```

SQLite 共用範本模式可手動執行：

```powershell
python -X utf8 .\sqlite_server.py --host 0.0.0.0 --port 8766
```

手動執行與雙擊啟動器都預設以 `0.0.0.0:8765` 監聽所有網路介面。需要刻意限制為僅供本機使用時，請改用：

```powershell
python -X utf8 .\server.py --host 127.0.0.1 --port 8765
```

本機開啟 <http://127.0.0.1:8765>。停止服務請在執行中的終端按 `Ctrl+C`。

每次啟動都會直接建立可填寫的空白案件，不會自動讀取根目錄的 `../data.txt`。SQLite 模式若設有非空白預設範本，會在空白案件建立後自動帶入。要編輯既有案件時，必須由使用者在畫面上主動選擇 `data.txt`、含有 `data.txt` 的二維系統 ZIP，或完整案件 JSON；匯入會整案覆寫且不再混入預設範本，根目錄檔案是否存在都不影響啟動內容。

`schema/data_txt_schema.json` 是 data.txt 匯入、驗證及匯出的唯一結構依據；`schema/case_extension_schema.json` 是完整案件 JSON 的 13 表外擴充契約。兩者應提交版控且不得放入任何案件值。需要依相容的 `data.txt` 重新抽取 13 表結構時，在本目錄執行：

```powershell
python -X utf8 .\tools\extract_schema.py
```

也可用 `--source C:\path\to\data.txt` 指定來源。服務啟動時若找不到 schema，會直接報錯，避免用不明欄序匯出資料。

## 區域網路／外網連線

`127.0.0.0/8` 是回環網段，只能由本機使用；`0.0.0.0` 才是伺服器接受所有網路介面的監聽設定，但它不是瀏覽器要輸入的網址。

使用任一啟動 BAT 後，終端會列出類似以下的網址；SQLite 模式的連接埠改為 `8766`：

```text
http://192.168.1.100:8765/
```

- 本機回環位址、RFC 1918 私有 IPv4（`10/8`、`172.16/12`、`192.168/16`）、IPv6 ULA（`fc00::/7`）與 link-local（`fe80::/10`）來源不需要權杖。
- 同一私有區域網路的電腦或手機，直接使用終端列出的 `http://內網IP:8765/`。
- 非上述私有網路來源仍須使用終端列出的本次啟動權杖；第一次成功驗證後，伺服器會把權杖放入僅供本站使用的 HttpOnly Cookie，並移除網址列上的 token。
- 權杖每次啟動都會重新產生；關閉終端即停止服務。若前方另有位於私有網路的反向代理，必須由代理本身負責認證，因為伺服器會將代理視為內網來源。
- 真正從網際網路連入，還需要在 Windows 防火牆允許 TCP 8765，並在路由器設定連接埠轉發，或使用 VPN／安全通道。啟動器不會自動修改防火牆或路由器。
- 本服務沒有 HTTPS。案件可能包含身分證字號、地址等個資，建議透過 VPN 使用，不建議直接把 8765 暴露在公網。

## 已完成的功能

- 預設進入空白案件；無資料庫模式下，案件主檔只保留格式需要的初始控制值，起造人、設計／監造建築師、承造人、技師及其他子表均為空白；SQLite 模式則可帶入非空白預設範本。
- 載入既有 CP950／Big5 `data.txt`，保留前端未顯示的系統／相容欄位。
- 可由按鈕或拖放直接載入二維系統 ZIP；ZIP 內必須只有一個檔名為 `data.txt` 的項目，所在子目錄不限。
- 從 ZIP 載入後可選擇單獨匯出 `data.txt`，或以更新後的 `data.txt` 替換原項目並重新封裝 ZIP；其他項目的內容、路徑與 ZIP 註解保持不變。
- 使用「全案清空」清除所有案件資料；確認後建立新的空白案件，SQLite 模式再帶入非空白預設範本。
- SQLite 模式可將起造人、設計／監造建築師、承造人、專業技師、案件備註與書表長文字的白名單欄位儲存為共用範本、設為各類別預設、更新、套用或刪除；一般模式不顯示自訂範本按鈕。
- 案件備註提供舊二維系統的 6 類分類、52 個「程序、屬性」及 89 則規定備註全文；依序選分類、程序與內容後可新增成一列，亦可直接新增自由備註。插入後仍可逐字修改，不會鎖死預設文字。
- 適用法令概要可編輯防火及防火避難版本、性能設計認可日期與文號，以及耐震設計規範版本；版本選項取自舊二維系統 `Build.mdb`。
- 書表長文字可編輯 A12 標題與 A12-5 標題；SQLite 模式可自行勾選要收入同一範本的欄位。
- 編輯 A／B／C／D／F／H 書表實際使用的 19 個資料群組；同一群組在不同書表組共用同一份案件資料。
- 側邊欄可切換 A 建照申請、B 施工管理、C 使用管理、D 拆除與其他；目前分別開放 11、12、11、9 個編輯入口，書表目錄仍直接取自 `ALLRPT`。切換只改變檢視，不會複製或清除案件資料。
- 左側資料群組會依案件主檔的申請類型，在建議優先填寫的名稱前加上 `*`；這是依已確認書表資料關聯提供的導引，不會隱藏、鎖定或禁止使用其他可能因個案條件需要填寫的群組。
- B 組可編輯共用案件／地號／人員資料、`BMSSC` 開竣工查報、`BMSROAD` 使用道路、`BMSCHK` 施工勘驗、`BMSSCRP` 逐月材料與人力、`BM_TEC` 專業技師，以及可一次多選上傳的施工照片／附件。
- C 組可編輯使用執照／變更使用欄位、`C21_3` 檢討項目與 `BMELVTR` 昇降／機械停車設備；D 組可編輯拆除執照、專業技師與農舍管制資料。
- 可載入與匯出 UTF-8 BOM「完整案件 JSON」；JSON 同時保存 data.txt 的 13 表與 `extraTables`，附件保留檔名、類型、大小及 Base64 原始內容。
- 依「縣市 → 行政區 → 地段」連動完整選項；構造、使用分區、用途、樓層、停車分類等也使用原程式代碼庫。
- 選項不超過 5 筆時直接顯示下拉選單（包含所有 Y／N 欄位）；超過 5 筆才使用固定高度的搜尋視窗，避免大量選項撐滿畫面。
- 主要畫面以中文名稱為主，原始欄名與直接代碼輸入預設隱藏，需要對接 CSV／XML 時可按「顯示原始欄名」開啟。
- 欄位區段可逐段或一鍵全部收合；填寫提醒與較長說明預設收起，減少畫面上的常駐備註。
- Modal 可點擊外側背景關閉；批次輸入的既有修改會保留在目前案件中。頁面及 modal 清單固定預留右側捲軸空間，避免內容寬度跳動。
- 選項以顯示名稱為主要排序鍵；名稱開頭是中文數字（含壹、貳、拾、佰等大寫）時依數值排序，前方已有其他中文字時則依繁體中文筆畫排序。
- 在重複資料群組使用「批次表格」，可一鍵全選／取消全選、一次新增 1／10 列、複製或刪除勾選列，也可直接貼上 Excel／TSV／CSV 的多列多欄資料。
- 基地地號、樓層概要與雜項工作物的批次表格可切換本次／變更前（原核准）資料；不一致的列會在核取方塊上方顯示紅點，不一致的欄位會在儲存格右下角顯示紅點，切換到任一側都能定位同一組差異。
- 上述批次表格可一鍵將全部列的本次資料帶入變更前／原核准欄位；空白值也會覆蓋，避免舊值殘留。
- 批次表格依欄位類型使用緊湊欄寬；棟別、樓層／行政代碼與數字欄約為舊寬度的 2/3，長備註欄才保留較寬空間。
- 每個資料群組都有「清空本頁」，會先顯示警告 Modal 並只清除目前頁面；案件主檔的系統連結主鍵會保留，其他頁面不受影響。
- 載入 UTF-8 或 Big5 的 CSV／TSV／XML，將來源欄位對接到任一目標資料群組。
- 由「下載範例 CSV／XML」產生 19 個資料群組各自可直接回匯的虛構範例。
- 匯出固定 13 表、596 欄、固定欄序、CRLF、CP950 的完整 `data.txt`；B／C／D 組額外資料不會混入舊格式。
- 匯出前檢查主鍵、序號、數字格式、代碼／顯示文字及 CP950 亂碼風險。
- 提供 PostgreSQL DDL、13 表 JSONB 投影 view，以及案件匯入／匯出與代碼落庫工具；一般模式不依賴資料庫，SQLite 模式也只保存共用範本。完整 PostgreSQL 操作方式見 `../db/README.md`。

## 多地號、多樓層快速輸入

1. 左側選「基地地號」或「樓層用途面積」等重複資料群組。
2. 按右上角「批次輸入」。
3. 可按「新增 10 列」先建立空列；也可以從 Excel 複製一塊資料後，點批次表格的起始儲存格直接貼上。
4. 貼上的第一列若是原始欄名或畫面中文欄名，會當作標題列，不會寫成資料。
5. 要整批複製或刪除時可按「全選」；全部選取後同一按鈕會改成「取消全選」。
6. 地號、樓層概要或雜項工作物可用上方切換按鈕查看本次／變更前資料；紅點表示該列或欄位兩側不同。
7. 要一次建立原核准資料，可按「全部帶入變更前／原核准」；會處理目前表格的每一列，不必逐筆切換記錄。
8. 完成時系統會重新編排 `person_seq`；有 `SPOKESMAN` 的表會將第一列設為 `Y`、其餘列設為 `N`。

地號請分別填 `DIST`、`SECTION`、`ROAD_NO1`、`ROAD_NO2`；樓層面積每個「樓層 × 用途」各一列，同一樓層可有多列。

## 一鍵帶入原核准資料

- 「基地地號 → 變更前地號」右側有「一鍵帶入本次地號」。它會依序將 `DIST`、`SECTION`、母號、子號、總面積、使用面積及兩組使用分區代碼複製到對應的 `*_OLD` 欄位。
- 「樓層／用途／面積 → 變更前／原核准樓層概要」右側有「一鍵帶入本次樓層概要」。它會複製棟別、樓層、三組用途代碼／說明／輔助值，以及面積、層高、陽台、露臺資料。
- 「雜項工作物 → 變更前／原核准工作物」也可一鍵帶入名稱、構造、尺寸、面積與說明。
- 這些按鈕都是逐欄覆蓋：本次欄位若為空白，對應原核准欄位也會被清成空白，避免殘留舊值。批次表格另提供全部列一次帶入。

## 搜尋選項

代碼欄依目前連動條件計算實際選項數量：5 筆以內直接使用下拉選單，6 筆以上才開啟固定高度的選項視窗。搜尋框永遠在視窗清單上方，可以輸入中文名稱或實際代碼；空格可組合多個關鍵字，例如搜尋 `福安 4662`。可用 `↑`、`↓` 移動並按 `Enter` 選取，最近選過的項目會顯示在上方。選取後欄位仍保存原系統要求的代碼，中文名稱只作辨識顯示；主畫面與批次輸入採用相同門檻。

## CSV／XML 對接方式

按「下載範例 CSV／XML」，選擇資料群組後下載：

- CSV：UTF-8 BOM、CRLF，第一列是真實欄名。
- XML：UTF-8，根節點為 `CPAMIImport`，每個資料列使用目標表名，例如 `<BMSLAN>`。
- 所有範例均為虛構資料，可以直接改值，再按「轉換 CSV／XML」回匯；真實欄名會自動一對一對應。
- 建議一個資料群組一個來源檔，不要把案件、地號、所有權人、樓層等不同列粒度塞進同一個超寬 CSV。

CSV／XML 是交換與編輯格式；最後按「匯出 data.txt」時才會轉成舊系統要求的 CP950、13 表固定結構。

## data.txt 與完整案件 JSON

- 「匯出 data.txt」永遠輸出完整 13 表、596 欄，包含畫面未顯示的相容欄位；目前切在哪個書表組都不影響輸出範圍。
- 只要案件主檔通過驗證，即使某一子表尚未填資料，匯出時也會建立一筆完整欄序的空白記錄，確保稀疏案件仍可重新匯入並核對全部 596 欄。
- `BMSROAD`、`BMSCHK`、`BMSSCRP`、`RPTPHOTO`、`C21_3`、`BMELVTR` 原本不在 data.txt 契約內，因此只保存在「完整案件 JSON」與 PostgreSQL payload。
- 要保留完整 B／C／D 系列草稿，請在「更多」選擇「匯出完整案件 JSON」；下次用「載入完整案件 JSON」可還原 13 表、擴充表及附件。
- 載入另一份 data.txt 會開始一個只有 13 表的新案件；若目前已有擴充資料，畫面會先警告，避免誤清除。

## 二維系統 ZIP

- 「載入 data.txt／ZIP」與整頁拖放都接受 `.zip`；ZIP 必須未加密，且只能有一個 basename 為 `data.txt` 的檔案。
- 原 ZIP 只保留在目前瀏覽器頁面的記憶體中，不會寫入專案目錄；重新整理、關閉頁面、載入純 `data.txt`、完整案件 JSON 或建立空白案件後，就不能再匯出原 ZIP。
- 「匯出」選單永遠可輸出單獨的 `data.txt`。只有從 ZIP 載入案件後，「匯出原 ZIP（替換 data.txt）」才會啟用，輸出檔名加上 `_updated.zip`。
- 案件內容沒有改動時直接回傳原 ZIP 的完整位元組，不重新封裝；有改動時只替換原路徑的 `data.txt`，其他項目以相同路徑與原始未壓縮位元組重新寫入，也不會帶入完整案件 JSON 的 `extraTables`。
- 舊二維的小型 ZIP 維持一般 ZIP 2.0 標頭，不會把 `verfile.txt` 等小檔強制標成 ZIP64；舊系統無法讀取的 ZIP64 標頭會造成匯入錯誤 517。
- 安全限制：ZIP 上傳連同案件資料不可超過 96 MB、項目不可超過 5,000 筆、解壓縮後總大小不可超過 512 MB，且 `data.txt` 不可超過 16 MB。

## 規定備註快速帶入

- 進入「案件備註」後，頁面上方會先顯示引導區：依序選擇「分類項目」→「程序、屬性」→「備註內容範本」，確認全文預覽後再新增。
- 6 類分類與其下 52 個程序、89 則內容來自舊二維系統 `Build.mdb` 的 `RMK` 資料；分類只用於前端過篩，寫回 `data.txt` 的仍是 `MEMO_SEQ`、`MEMO_SEQ_NAME`、`DESE` 三欄。
- 同一程序若只有一則預設內容會自動選取；選項較多時沿用可搜尋、鍵盤操作與最近使用項目的選項視窗。
- 「新增這則備註」優先使用空白列，沒有空白列才建立新列，不會覆蓋其他已填備註。加入後仍可直接修改代碼、名稱與全文。
- 不屬於規定清單的內容可按「新增自由備註」。SQLite 模式另可把目前這一列存成自訂案件備註範本；套用時預設新增一列，只有明確允許覆蓋才會改寫目前列。

## SQLite 共用資料範本

- 以 `Start_CPAMI_Editor_SQLite.bat` 啟動後，在起造人、設計建築師、監造建築師、承造人、專業技師、案件備註與書表長文字頁面會出現範本按鈕。
- 儲存與更新都只取目前記錄，後端再用各類別 allowlist 過濾；`INDEX_KEY`、各種 `person_seq`、`SPOKESMAN`、識別碼、建立／更新日期、操作人員及案件專屬欄位不會入庫。起造人另排除棟別、戶號、建物門牌與用途關係。
- 每一類別可有多個範本，但同一時間只能有一個預設範本。預設範本只在初始空白案件及「全案清空」後帶入；沒有非空白預設範本時不建立該資料列。
- 人員／單位與書表長文字範本預設只填目前空白欄位；只有明確勾選「允許覆蓋目前已有內容」才會覆蓋。案件備註範本則預設新增一列，避免誤蓋既有備註。
- 書表長文字在儲存範本時可勾選只保存 `A12_TITTLE`、只保存 `A12_5TITLE`，或兩者都保存；未勾選的欄位不會被套用。
- 載入 data.txt、ZIP 或完整案件 JSON 都會直接取代目前案件，不會套用預設範本。CSV／XML 仍依使用者選擇取代或附加單一資料群組。
- 完整案件仍只存在各瀏覽器分頁的記憶體，使用者必須自行匯出 data.txt、ZIP 或完整案件 JSON。這個暫時版本沒有案件清單、多人協作鎖定或案件權限。
- SQLite 檔案位於 `runtime/sqlite/` 且已忽略版控；其中可能包含姓名、身分證字號、地址與電話，應納入內部備份與存取控管，不得提交 Git 或外傳。
- 私有內網依目前設定不需權杖，因此同一可信內網中能開啟 WebUI 的人也能新增、更新或刪除共用範本。暫時版本沒有個別帳號、範本權限、修改紀錄或衝突鎖定；若要跨不受信任人員使用，應等正式後端接上身分驗證與權限後再開放。

未來改接 PostgreSQL 時沿用相同欄位邊界，詳細契約見 `../docs/POSTGRES_INTEGRATION_PLAN.md` 的共用範本規劃。

## 重新產生下拉代碼檔

Access MDB 使用 32 位元 Jet Provider，請以 32 位元 Windows PowerShell 執行：

```powershell
$env:CPAMI_BUILD_MDB_PASSWORD = Read-Host "Build.mdb password"
& "$env:WINDIR\SysWOW64\WindowsPowerShell\v1.0\powershell.exe" `
  -NoProfile -ExecutionPolicy Bypass `
  -File .\tools\export_codebook.ps1 `
  -DatabaseRoot ..\cpami\Arch2016C `
  -BuildDatabasePath ..\cpami\Arch2016C\Build.mdb `
  -OutputPath .\web\codebook.json `
  -TaichungSectionsCsv .\reference\taichung_land_sections_2026-05-12.csv
Remove-Item Env:CPAMI_BUILD_MDB_PASSWORD
```

密碼只透過本次 PowerShell 行程的環境變數傳入，不要寫進腳本、文件或版控。若省略 `BuildDatabasePath`，仍可產生一般代碼，但不會含規定備註與補充法令選項。
