## 30 秒快速上手

需求：**Python 3.11+**（只用標準庫）、**Node.js**（只用來跑前端測試）。
沒有 npm 執行期相依、沒有 pip 套件、沒有建置步驟。

```bash
git clone https://github.com/Archwiz-boss/BOOKTIRE.git
cd BOOKTIRE/cpami-form-editor

# 啟動（預設 0.0.0.0:8765，只想給本機用就加 --host 127.0.0.1）
python -X utf8 ./server.py --host 127.0.0.1

# 或是使用者友善的啟動器（預設只綁本機、自動開瀏覽器、自動找可用埠）
python -X utf8 ./launcher.py
```

瀏覽器開 <http://127.0.0.1:8765>。

改完之後跑測試：

```bash
cd cpami-form-editor
node --check ./web/app.js
node ./tests/frontend_smoke_test.js
python -X utf8 ./tests/core_unit_test.py
python -X utf8 ./tests/sqlite_template_test.py
python -X utf8 ./tests/network_access_test.py
# 先另開一個視窗跑 server.py，再跑這個
python -X utf8 ./tests/server_roundtrip_test.py
```

## 這個專案在解什麼問題

內政部營建署（CPAMI）建照電子申請舊系統的案件資料格式是 `data.txt`：

- 編碼 **CP950／Big5**，無 BOM，CRLF 換行
- **13 張表、596 個欄位**，順序完全固定
- 語法：`@TableName 表名` / `@RecordBegin` / `@d 欄名 "值"` / `@RecordEnd`
- 一份 `data.txt` = 一個案件

A（建照申請）、B（施工管理）、C（使用管理）、D（拆除）這些「書表組」
**不是不同的案件，而是同一份案件資料的不同檢視**。這是理解整個專案的關鍵。

### 分層鐵則

這幾條決定了程式該寫在哪裡，請務必遵守：

| 規則 | 原因 |
|---|---|
| **格式知識只住在 `cpami_core.py`** | CP950 編碼、欄序、驗證規則只有一份實作。前端永遠只碰 JSON 與 UTF-8，**不做任何編碼工作** |
| **`web_api.py` 不得引入 HTTP／伺服器／瀏覽器相依** | 因為桌面版（`server.py`）與線上試用版（Pyodide）都呼叫它。加了傳輸層相依，試用版就會壞 |
| **`server.py` 只做傳輸、授權、檔案服務** | 業務邏輯往 `web_api.py` 放 |
| **代碼的唯一來源是 `web/codebook.json`** | 只能用 `tools/export_codebook.ps1` 重新產生，**不得手改內容**。`app.js` 裡的 `CODE_OPTIONS` 僅作缺漏備援 |
| **書表目錄的唯一來源是 codebook 的 `ALLRPT`** | 109 筆。新增書表組時從這裡取清單，不要照畫面截圖手抄 |
| **一般模式 `server.py` 禁止引入資料庫相依** | 必須能在離線 Windows 工作站執行 |

## 資料流

```
                    ┌─────────────────────────────────────┐
                    │  瀏覽器（app.js）                    │
                    │  只碰 UTF-8 JSON，不做編碼           │
                    └───────────────┬─────────────────────┘
                                    │ fetch /api/*
              ┌─────────────────────┴─────────────────────┐
              │                                           │
    ┌─────────▼──────────┐                     ┌──────────▼─────────┐
    │ 桌面版              │                     │ 線上試用版          │
    │ server.py           │                     │ demo-adapter.js     │
    │ （HTTP 傳輸／授權） │                     │ （攔截 fetch）      │
    └─────────┬──────────┘                     └──────────┬─────────┘
              │                                           │ Pyodide (WASM)
              └─────────────────┬─────────────────────────┘
                                │
                    ┌───────────▼────────────┐
                    │  web_api.py            │  ← 兩邊共用的同一份實作
                    │  bootstrap / import /  │
                    │  validate / export     │
                    └───────────┬────────────┘
                                │
                    ┌───────────▼────────────┐
                    │  cpami_core.py         │  ← 格式引擎，唯一真實來源
                    │  CP950 ⇄ Python dict   │
                    └────────────────────────┘
```

**重點**：試用版不是另一套實作。它把**同一份 `cpami_core.py` 與 `web_api.py`**
丟進瀏覽器裡的 CPython（WebAssembly）執行。因此格式規則永遠只有一份，
不會出現「網頁版跟桌面版行為不一樣」的問題。

### API 一覽

| 端點 | 方法 | 用途 |
|---|---|---|
| `/api/bootstrap` | GET | 取得 schema、空白案件、範本儲存狀態 |
| `/api/health` | GET | 健康檢查 |
| `/api/import-data-txt` | POST | CP950 `data.txt` → JSON |
| `/api/import-zip` | POST | ZIP 內的 `data.txt` → JSON |
| `/api/import-case-json` | POST | 完整案件 JSON → JSON |
| `/api/validate` | POST | 驗證，回 errors／warnings |
| `/api/export` | POST | JSON → CP950 `data.txt` |
| `/api/export-zip` | POST | JSON + 原 ZIP → 替換過 `data.txt` 的 ZIP |
| `/api/templates*` | CRUD | 共用範本（僅 SQLite 模式） |

## 不可協商的格式鐵則

**違反其中任何一條，產出的檔案舊系統就會拒收。改動前請先讀完。**

1. **13 表全保留**，順序與模板一致；每表欄位集合與順序固定，合計 596 欄。
2. 語法固定：`@TableName 表名` / `@RecordBegin` / `@d 欄名 "值"` / `@RecordEnd`；
   **CRLF** 換行，檔尾保留 CRLF。
3. 編碼 **CP950／Big5、無 BOM**。無法表示的字元**必須報錯**，
   不可默默變成 `?`。
4. 值內**禁止**半形雙引號與實體換行（舊格式沒有跳脫規則）。
5. 空值是 `""`，**不可**擅改為 `"0"`。所有值一律是字串——
   前導零（例如 `LAST_MODIFY` 的 `00001`）與「空白 vs 0」的差異都必須保真。
6. `INDEX_KEY` 全 13 表一致；子表的 `person_seq`／`PERSON_SEQ`／`Person_seq`
   為正整數且同表不重複。
7. 數字欄純數字（不含單位、千分位）；日期多為民國 `yyyMMdd` 7 碼。
8. ⭐ **位元組級 roundtrip 是最高驗收標準**：
   載入一份合法 `data.txt` 不經修改直接匯出，**必須逐位元組相同**。
9. 欄名（含 `person_seq`、`eMail` 等大小寫不一致者）是舊系統契約，
   **禁止「訂正」拼寫或大小寫**。
10. 前端未顯示的系統／相容欄位（含 `BM_TEC`、`BMSSC`）
    在載入、編輯、匯出全程保留原值。
11. 匯出時即使某子表沒有使用者資料，也要輸出一筆完整欄序的空白記錄。
12. 從 ZIP 載入後若 `data.txt` 未改動，匯出必須**逐位元組回傳原 ZIP**；
    有改動才替換 `data.txt`。小檔案**不得**被標成 ZIP64，
    否則舊系統會以**錯誤 517** 拒絕匯入。

> 欄位語意與代碼對應，一律以根目錄的
> [`CPAMI_data_txt_欄位與代碼對應表.md`](../CPAMI_data_txt_欄位與代碼對應表.md) 與
> [`CPAMI_指定書表_實用數據對應表.md`](../CPAMI_指定書表_實用數據對應表.md) 為準。
> **文件沒寫的不要猜**——回原系統的 `.fr3` 報表模板與 MDB 查證。

## 測試與驗收

在 `cpami-form-editor/` 目錄執行：

| 指令 | 什麼時候必跑 |
|---|---|
| `node --check ./web/app.js` | 改 `app.js` |
| `node ./tests/frontend_smoke_test.js` | 改前端 |
| `python -X utf8 ./tests/core_unit_test.py` | 改 `cpami_core.py`／`web_api.py` |
| `python -X utf8 ./tests/sqlite_template_test.py` | 改範本功能 |
| `python -X utf8 ./tests/network_access_test.py` | 改連線與授權邏輯 |
| `python -X utf8 ./tests/server_roundtrip_test.py` | 改伺服器或匯出邏輯（**需先啟動 server.py**） |
| `python -X utf8 ./tests/pg_tools_test.py` | 改 PostgreSQL 工具 |
| `node ./tests/demo_pyodide_test.mjs` | 改 `cpami_core.py`／`web_api.py`／轉接層（**需先 `npm install`**） |

規則：

- **改了行為就同步改測試斷言。**
- 測試主體**只能使用版控內的虛構 fixture**，不得依賴真實個資。
- 虛構資料沿用既有慣例：「範例建設股份有限公司」「王範例」「A123456789」
  「臺中市範例區範例路」。

## 常見二次開發任務

### 我想改畫面樣式

改 `web/styles.css`。**一律使用既有的 CSS 變數**，不要引入新的裸色碼：

| 變數 | 用途 |
|---|---|
| `--navy` | 頂欄 |
| `--amber` | 主要動作 |
| `--paper` / `--canvas` | 背景 |
| `--green` / `--red` | 狀態 |

### 我想加一個欄位到現有的資料群組

1. 確認該欄位**存在於 `schema/data_txt_schema.json`** 的該表欄序中。
   如果不存在，它就不屬於 data.txt 的 596 欄——**不可以硬加**，
   請改放到 `case_extension_schema.json`（只會存在完整案件 JSON 裡）。
2. 在 `app.js` 的 `TABLE_CONFIG` 對應區段用欄位 DSL 加上去。
3. DSL 型別：`F` 文字、`N` 數字、`D` 日期、`C` 代碼、`Y` 是否、`M` 多行、`S` 選單。
4. 跑 `node --check` 與前端煙霧測試。

### 我想新增一個書表組

1. **先產出對應表研究文件**（比照
   [`CPAMI_指定書表_實用數據對應表.md`](../CPAMI_指定書表_實用數據對應表.md) 的格式）。
2. 書表清單從 codebook 的 `ALLRPT` 取，**不要照畫面截圖手抄**。
3. 不在 data.txt 13 表內的資料，**一律先列缺口，經決策後**才能新增儲存格式。
4. 既有 A 組的行為不得回歸。

### 我想改代碼庫（下拉選單內容）

**不要手改 `codebook.json`。** 用 32 位元 PowerShell 重新產生：

```powershell
$env:CPAMI_BUILD_MDB_PASSWORD = Read-Host "Build.mdb password"
& "$env:WINDIR\SysWOW64\WindowsPowerShell\v1.0\powershell.exe" `
  -NoProfile -ExecutionPolicy Bypass `
  -File .\tools\export_codebook.ps1 `
  -DatabaseRoot ..\cpami\Arch2016C `
  -BuildDatabasePath ..\cpami\Arch2016C\Build.mdb `
  -OutputPath .\web\codebook.json `
  -TaichungSectionsCsv .\reference\taichung_land_sections_2026-05-12.csv
Remove-Item Env:CPAMI_BUILD_MDB_PASSWORD
```

> 需要自備舊系統的 MDB（不在版控內，見 [NOTICE.md](../NOTICE.md)）。
> 密碼只透過本次行程的環境變數傳入，**不要寫進腳本、文件或版控**。

### 我想接資料庫

- **PostgreSQL**：DDL、13 表 JSONB 投影 view、案件匯入匯出工具都在 `db/` 與
  `cpami-form-editor/tools/`。規劃見
  [`POSTGRES_INTEGRATION_PLAN.md`](POSTGRES_INTEGRATION_PLAN.md)。
- **SQLite（共用範本）**：`sqlite_server.py`。
  **SQLite 不得保存完整案件**，執行期檔案只放在已忽略版控的 `runtime/`。

### 我想改成別的縣市 / 別的用途

代碼庫目前補了臺中市的官方地段資料。要換成其他縣市，
把該縣市的地段 CSV 餵給 `export_codebook.ps1` 的 `-TaichungSectionsCsv` 參數即可
（參數名稱沿用歷史命名，內容不限臺中）。

## 打包 exe

```powershell
powershell -ExecutionPolicy Bypass -File .\tools\build_exe.ps1
```

腳本會自動：檢查／安裝 PyInstaller → **先跑回歸測試（不過就不打包）** →
PyInstaller 單檔打包 → **啟動產出的 exe 打 `/api/health` 驗證** → 清理暫存。

產出：`dist\CPAMI-Editor.exe`（約 10 MB）。

技術細節：

- 使用 `--onefile`，執行期會解壓到暫存目錄。因此**唯讀資源**（`web/`、`schema/`）
  走 `sys._MEIPASS`，**可寫入的資料**（`runtime/`）走 exe 所在目錄——
  這個差異封裝在 [`app_paths.py`](../cpami-form-editor/app_paths.py)。
- 入口是 `launcher.py` 不是 `server.py`：預設只綁 `127.0.0.1`、自動找可用埠、
  自動開瀏覽器、例外不讓視窗直接關掉。
- Windows 主控台預設 cp950 會讓說明文字裡的框線字元爆掉，
  `launcher.py` 啟動時會把主控台切成 UTF-8。

> `dist/` 已被 gitignore。exe 以 GitHub Release 發布，不進版控，
> 避免每次改版都在 git 歷史裡永久累積 10 MB。

## 線上試用版怎麼運作

```powershell
python -X utf8 tools/build_demo.py     # 產生 _site/
```

`build_demo.py` 從桌面版**原地複製** `web/`、`schema/`、`cpami_core.py`、
`web_api.py`，再加上 `web-demo/` 的轉接層與載入畫面，
並在 `index.html` 注入提示條與 `<script src="demo-adapter.js">`。

**試用版沒有自己的前端副本**——改桌面版就等於改試用版。

`demo-adapter.js` 做三件事：

1. 從 CDN 載入 Pyodide（WebAssembly 版 CPython 3.14）
2. 把 `cpami_core.py`、`web_api.py`、schema 寫進 Pyodide 的虛擬檔案系統
3. 覆寫 `window.fetch`，把 `/api/*` 導向 Python，其餘照常走網路

因為 `app.js` 所有請求都走 `fetch`，**不需要改 `app.js` 一行程式**。

驗證：`node ./tests/demo_pyodide_test.mjs` 會把轉接層裡真正送進瀏覽器的
那段 Python 抽出來跑，確認 13 表 596 欄、data.txt 與 ZIP 的位元組級 roundtrip、
以及 400／404 錯誤狀態都與桌面版一致。

部署由 `.github/workflows/pages.yml` 自動處理（推上 `main` 就重新部署）。

## 程式風格

### JavaScript（`app.js`）

- **單一檔案**，區段順序固定：
  欄位 DSL（`F`/`N`/`D`/`C`/`Y`/`M`/`S`）→ `TABLE_CONFIG` 等設定表 → `state`
  → 工具函式 → `render*` → 事件註冊 → `bootstrap()`
- 新功能沿用同一 DSL 與區段結構，**不引入模組打包**
- 所有插入 DOM 的動態字串**必經 `escapeHtml`**

### Python

- `from __future__ import annotations`、型別註記、**只用標準庫**
- 格式錯誤一律拋 `DataTxtError`，帶**中文行號訊息**

### UI 文案

- 繁體中文、全形標點
- 面積用「㎡」、長度用「m」
- 按鈕文字精簡（「新增 10 列」「一鍵帶入本次地號」的風格）

### 註解

**只寫「程式看不出來的限制」**（例如 `BUILDING_NO` 在不同表的語意差異、
ZIP64 會造成錯誤 517），不寫流水帳。

### Commit 訊息

沿用 `feat:` / `fix:` / `refactor:` / `docs:` 前綴。

## 個資與安全紅線

- 根目錄的 `data.txt`（如果你有）是真實案件：
  **不得提交進 git、不得貼進雲端服務、不得出現在測試碼與文件範例中。**
- `cpami/` 是第三方程式與真實案件輸出：**唯讀、不入版控。**
- `authorize_request` 僅允許回環位址、RFC 1918 私有 IPv4、IPv6 ULA／link-local
  免權杖。**其他來源的一次性權杖與 HttpOnly／SameSite Cookie 機制不得移除或弱化。**
- 本服務**沒有 HTTPS**，文件必須持續提醒以 VPN／可信內網使用。
